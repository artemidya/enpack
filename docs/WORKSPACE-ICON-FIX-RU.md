# Иконка DirectEnpack в рабочем пространстве CorelDRAW 27

Проверка: **8 октября 2026**. Входной файл — `05-10-2026.cdws` из `artemidya/enpack`, commit `45ac190e3862a95c3dbb75386e3c5333805f765b`.

## Что найдено

CDWS — ZIP-архив рабочего пространства, а не установщик исполняемого кода CPG.

В `content/workspace.xml` обнаружены **три определения команды DirectEnpack** с категорией плагинов `ab489730-8791-45d2-a825-b78bbe0d6a5d`:

| GUID команды в рабочем пространстве | Иконка до исправления |
|---|---|
| `b1b5324f-9d4c-4d61-866f-16d56527c787` | атрибут `icon` отсутствует |
| `8492eb7e-d791-4d98-bb40-0d51470ee1ba` | атрибут `icon` отсутствует |
| `f6e128f8-eff9-4d84-8005-4cc9b33fad4c` | атрибут `icon` отсутствует |

Две из этих записей используются в панелях; третья также сохранена среди определений. Оригинальный `icon.ico` DirectEnpack отсутствует среди файлов `content/icons/`. Для других пользовательских кнопок этот же архив содержит ссылки вида `icon="guid://..."` и соответствующие `.ico`.

**Подтверждена отсутствующая привязка изображения в предоставленном CDWS.** Это объясняет стандартный значок у импортируемой кнопки, но не устанавливает, почему назначение иконки через CPG не произошло либо было потеряно: для этого нужен журнал запуска и проверка в CorelDRAW.

## Почему недостаточно иконки внутри CPG

Оригинальная иконка действительно есть как последовательность байтов `ICOData`:

- в загруженном пользователем `DirectEnpackx64.cpg`;
- в ранее выданной диагностической сборке.

В обоих проверенных бинарниках оригинальные 198 байт встречаются один раз, начиная со смещения 1424. Рисунок не был потерян при пересборке.

В исходнике `Resources.inc` используется `ICOData file 'icon.ico'`. При старте плагин сохраняет эти байты во временный файл и вызывает `Control.SetIcon2` **для выбранного экземпляра кнопки**. Это не автоматическая регистрация общей картинки для всех кнопок команды, добавленных импортом рабочего пространства. В оригинальном README автора также описан сброс значка после отмены настройки панелей.

Отсутствие атрибутов в CDWS нельзя исправить простым повторным включением тех же байтов ICO в CPG. Поэтому здесь сделана локальная правка рабочего пространства, без новой пересборки алгоритма.

## Как проверить

**Сначала экспортировать текущее рабочее пространство в резервную копию.** Исправленный CDWS — полный снимок присланного файла, а не маленькое дополнение: его импорт может вернуть старые настройки, если после экспорта исходного файла они менялись.

1. Скачать исправленный `.cdws`.
2. Импортировать тем же способом, которым был импортирован исходный файл, предпочтительно в отдельное тестовое рабочее пространство. Существующий `.cpg` оставлять установленным; CDWS его не заменяет.
3. Проверить изображение кнопки сразу после импорта и после перезапуска CorelDRAW.
4. Создать тестовый документ, выделить несколько объектов и нажать кнопку. Сообщить отдельно: **иконка появилась? окно раскроя открывается?**

Если не хочется импортировать полное рабочее пространство, использовать отдельно выданный `.ico` в настройках изображения существующей кнопки либо подготовить актуальный экспорт рабочего пространства для такой же точечной правки.

Если изображение всё ещё стандартное, нужен журнал `%TEMP%\DirectEnpack-27.log` от диагностической сборки. Если окно раскроя не открывается, нужно отдельно проверять загрузку CPG: наличие кнопки после импорта не доказывает, что плагин загружен.

Для отката переключиться на сохранённое рабочее пространство или импортировать свою резервную копию. Переустановка CorelDRAW и сброс всех настроек не нужны.
