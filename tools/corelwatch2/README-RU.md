# CorelWatch 2.0.1 — диагностика зависания при открытии файлов

Для CorelDRAW Technical Suite 27 / Windows 10–11 x64. Запускается отдельно от CorelDRAW, даже когда его интерфейс уже завис. Ничего не копировать в Addons. Не нужен Python или дополнительный .NET: используется штатный Windows PowerShell 5.1.

**Это сборщик диагностических данных, не автоматический ремонт и не перехватчик всех ошибок.** Не обещает определить виновный плагин без анализа. Главный интерфейс может отвечать Windows, хотя загрузка меню/докеров остановилась; поэтому есть ручная отметка зависания и проверка дочерних окон. Автотесты Windows выполняются без настоящего CorelDRAW.

## Исправление запуска в 2.0.1

Исправлена ошибка `Join-Path ... Path ... пустую строку` при запуске без параметров. Папка Reports теперь определяется после обработки параметров, по расположению самого скрипта, а не по текущей папке CMD. В случае ошибки запускатель больше не утверждает, что отчёт уже создан.

Распакуйте новую версию в отдельную папку. CPG, рабочую среду и настройки Corel для этого исправления менять не нужно.

## Для нынешней проблемы

1. Полностью распакуйте ZIP в отдельную папку, например «Загрузки\CorelWatch2». Не запускайте из архива.
2. Запустите **Start-CorelWatch.cmd**. Обычно права администратора не нужны. Если Corel запущен с повышенными правами, часть данных может быть недоступна — это будет записано; автоматического повышения прав нет.
3. Если Corel уже завис — оставьте его пока запущенным. Иначе запустите Corel и откройте **копию** небольшого файла.
4. Когда файл виден, но интерфейс/панели не работают, переключитесь в **окно CorelWatch** и нажмите **H**. Если снимок уже выполняется, подождите его окончания (до 20 секунд) и нажмите H ещё раз.
5. Подождите примерно 10–20 секунд, нажмите **Q** в окне монитора. При необходимости он дождётся текущего снимка и создаст ZIP.
6. В папке **Reports** рядом с программой появится папка сеанса и одноимённый **ZIP отчёта**. Проверьте их на личные данные и отправьте этот ZIP для анализа. Не нужно присылать сам CDR или всю папку пользовательского профиля.

Клавиши действуют только в собственном окне монитора: **H/S** — подробный снимок, **M** — отметка времени, **Q** — закончить и упаковать. Перехвата клавиатуры нет. Без Corel монитор ждёт запуска. По умолчанию работает до 20 минут; закрытие консоли сохраняет уже записанные строки, но финальная упаковка может не выполниться.

## Обратимая проверка новых надстроек

F8 сам по себе не исключает влияния CPG из Addons. Не выполняйте новые сбросы/переустановку и не удаляйте AppData ради первого теста.

1. Сначала получите отчёт **в зависшем состоянии**, если это возможно.
2. Закройте CorelDRAW полностью. Если требуется принудительное завершение, **несохранённые изменения могут быть потеряны**; монитор Corel не завершает.
3. Переместите `WEBP4CDRx64.cpg` и `Bleedsx64.cpg` из Addons **вашей фактически запускаемой Technical Suite** в отдельную резервную папку ВНЕ Addons. Не просто переименовывайте их, оставляя внутри дерева Addons. Остальные файлы не трогайте.
4. Запустите Corel и откройте ту же копию файла. Сделайте второй отчёт, например:

```bat
Start-CorelWatch.cmd -Label without-new-cpg -DurationMinutes 5
```

5. Если проблема исчезла, возвращайте новые CPG **по одному**, каждый раз полностью перезапуская Corel. Если не исчезла, это не доказывает исправность остальных компонентов — сначала сравним отчёты. Не удаляйте рабочие DirectEnpack/SmartDepart и профиль вслепую.

Сам монитор плагины не перемещает и настройки не меняет. Список загруженных модулей в отчёте покажет, действительно ли прежний CPG больше не загрузился; наличие модуля не доказывает его вину. Фильтр `SC_x64.8bf` расположен отдельно в Plugins; папки поиска 8bf не перебираются автоматически.

## Что добавлено по сравнению с CorelWatch 1

- **H** для зависшего интерфейса, даже если главное окно отвечает на WM_NULL.
- Подробные снимки в **отдельном вспомогательном процессе**, с ожиданием до 20 секунд. Если сборщик завис, завершается только созданный монитором сборщик, не CorelDRAW. Уже записанные этапы остаются.
- Точный путь и файловая версия запускаемого CorelDRW.exe; модули и SHA-256 загруженных CPG/8bf на диске.
- Инвентаризация Addons рядом с фактическим EXE: помогает заметить дубликаты. Не является доказательством загрузки каждого файла.
- Окна, владельцы, включённость, скрытые/внеэкранные окна и до 64 дочерних окон с ограниченной WM_NULL-пробой. Отключённое главное окно может означать нормальный модальный диалог, а не зависание.
- Состояния потоков и **Windows Wait Chain Traversal (WCT)** для максимум 24 потоков, GUI-потоки в приоритете. В некоторых случаях видны ожидания синхронизации/SendMessage и циклы.
- ZIP отчёта создаётся автоматически после Q. Ничего не отправляется по сети.

**WCT — не стек вызовов.** Он не показывает все виды блокировок, не локализует автоматически строку кода/CPG, может возвращать «нет доступа» и не гарантирует обнаружение deadlock. Отсутствие цепочки или цикла не означает, что Corel исправен. Для точного ответа впоследствии может понадобиться дамп памяти и отладчик; это отдельный согласованный шаг, здесь дампы НЕ создаются.

## Файлы отчёта

- `session.json`, `samples.jsonl`, `events.jsonl`, `summary.json` — параметры, время проблемы, CPU/память, ответы главного окна, запуск/исчезновение процессов, статусы сборщика.
- `capture-XX-pidNN/process.json` — версия и путь EXE.
- `modules.json` — загруженные модули, пути, адреса и хеши CPG/8bf.
- `addons-on-disk.json` — файлы в Addons; не список гарантированно загруженных плагинов.
- `windows.json`, `child-windows.json` — состояние окон/потоков интерфейса без заголовков и текста документов.
- `threads.json`, `wait-chains.json` — состояния потоков и частичные цепочки ожидания.
- `complete.json` — снимок завершён; файлы `*-error.json`, `helper-error.txt` и событие `capture_timeout` объясняют неполный снимок.
- `windows-events.jsonl` — доступные события Application 1000/1001/1002/1026 за сеанс, содержащие CorelDRW/DirectEnpack.
- `DirectEnpack-27-tail.log` — ограниченный хвост старого диагностического журнала, если есть; может содержать предыдущие сеансы.
- `READ-FIRST.txt` — краткие правила интерпретации.

JSONL ограничены суммарно 50 МиБ. Не более 8 подробных снимков за сеанс, каждый до 8 МиБ JSON; список модулей до 2048, Addons до 512 файлов, потоков до 256. При достижении лимита снимков начните новый сеанс. Одновременно работает только один сборщик; при нескольких экземплярах Corel снимок занятого процесса может быть пропущен — для воспроизведения лучше один экземпляр. Обычная занятость при загрузке большого CDR тоже может вызвать автоматический снимок: это наблюдение, не диагноз.

## Приватность и безопасность

Нет внедрения DLL, COM/VBA-вызовов в Corel, глобальных hooks, чтения текста/содержимого документов, скриншотов, дампов, автозагрузки или сетевой отправки. Нет изменения реестра, профиля, плагинов или аудита Windows. Сохраняются только локальные отчёты; Add-Type использует временные файлы компиляции Windows.

**Пути модулей, списки Addons и события Windows могут содержать имя пользователя, пути документов и другие личные сведения.** Просмотрите отчёт перед отправкой. Дамп, если позже понадобится, может содержать сами документы и данные лицензий — не публикуйте его на GitHub/в открытом чате.

Не отключайте антивирус и корпоративные ограничения. ExecutionPolicy Bypass в запускателе действует только на этот процесс PowerShell, не меняя системную политику; не обходите запрет организации. При ошибке пришлите текст консоли. После завершения утилиту и отчёты можно удалить: Corel и его настройки не изменятся.
